# CrossFrame ProMax README 首页设计

日期：2026-07-24

状态：设计已获用户批准

## 目标

把仓库 README 首页从“Suite 总览中附带介绍 ProMax”调整为“先建立 ProMax 是可运行、可审计、可修复的重型 AI 结构推演系统，再说明它属于 CrossFrame skill 家族”。首页必须准确说明 ProMax 的 v8-only 知识面、运行闭环、完整能力、使用成本与共创来源。

## 核心定位与署名

首屏主定位固定为：

> 可运行、可审计、可修复的重型 AI 结构推演系统。

首屏同时说明它不是要求模型“多想一会儿”的普通提示词，而是将 v8 知识、推演工件、反方攻击、明确裁决与机器验证组成独立 runtime。

共创署名使用人机共创表述：

> 由 CrossFrame 作者与 ChatGPT 5.6 Sol（Ultra）共同设计、实现、攻击与验证。

署名不得暗示 CrossFrame v8 的理论定义由模型原创，也不得把模型名称写成运行时依赖。模型名称只描述本次 ProMax skill 的设计与工程实现来源。

## 首页信息架构

README 顶部采用“技术白皮书”方向，按以下顺序展开：

1. ProMax 主标题、系统定位、版本与运行状态徽章。
2. 作者与 ChatGPT 5.6 Sol（Ultra）的共创署名。
3. 四项可核验规模指标：3,980 条全源读取事件、709 个概念、P0–P11 状态机、五向检索。
4. 从请求到验证修复的运行链。
5. “完整能力”矩阵，解释每项能力解决什么模型失真。
6. “如何抑制模型自身风味”模块，说明固定知识、角色隔离、反方攻击、立场冻结与验证器的作用。
7. 精确触发方式、环境依赖与高消耗警告。
8. Suite/Max/ProMax 的边界与原有详细文档导航。

原有 README 的安装、场景、工作流、Max、Skill 地图与文档部分继续保留，避免破坏已有使用者入口；只重构首页前部并补强 ProMax 专区。

## 视觉语言

- 依赖 GitHub 原生 Markdown、HTML 对齐、表格、代码块、`details` 和 Shields 徽章，不引入需要维护的外部主视觉图片。
- 使用冷色技术白皮书风格：靛蓝表示知识与运行时，青绿表示验证通过，琥珀表示显式触发与成本警告。
- 首屏保持高信息密度，但每个数字必须附带语义，不能只作为装饰。
- 视觉层级按“定位 → 证据 → 能力 → 使用”组织，不用大量同级标题或重复徽章。
- 中文为主，英文只保留 runtime、artifact、validator、skill ID 与标准字段名。

## 完整能力矩阵

能力说明至少覆盖以下八组：

| 能力 | README 必须讲清的实现 |
| --- | --- |
| v8 全源加载 | 固定源快照、3,863 个段落、117 张表、读取事件与散列绑定 |
| 概念闭包 | 709 个概念逐项处置，读取权威定义、邻接关系、误用边界与请求绑定理由 |
| 局部世界建模 | 对象、行动者、圈层、尺度、双通道、时钟、事件、证据和未知项 |
| 命题与推演 | 中心命题、竞争机制、路径 DAG、条件前瞻、切换与撤回条件 |
| 真实检索 | 五向检索、案例校准、支持与反例分离；网络缺失时诚实降档 |
| 自我攻击 | 最强反方、概念误用攻击、正反立场稳定性和证据截止点 |
| 明确裁决 | 攻击后冻结立场，比较六类行动方案，给出首选、次选、停止与回滚条件 |
| 可验证交付 | dossier、concept atlas、案例与反例、完整 essay、manifest、fresh validator 与阶段感知修复 |

## 可信度与边界

- 所有规模数字从已提交的 v8 manifest、registry、状态机或测试结果取得。
- 不声称“无限算力”“绝对穷尽”或“保证最优”，只说明可验证的预算内饱和与闭环能力。
- “ChatGPT 5.6 Sol（Ultra）”是共创署名，不是 ProMax 的唯一兼容模型；其他 Agent 型 AI 也可调用。
- DeepSeek V4 Pro 约 17,000,000 token 是用户提供的单次完整运行实测，必须标为观测值而非通用基准。
- 法律、医疗、财务等高责任结论仍受证据档位、撤回条件与行动上限约束。

## 验证

实施完成后执行：

1. README 锚点与仓库内部链接检查。
2. ProMax 数字与源 manifest、概念 registry、CI 测试结果交叉核对。
3. 仓库完整性检查与 `git diff --check`。
4. 在 GitHub Markdown 兼容范围内检查 HTML、表格、`details` 与徽章语法。
5. 确认既有 Max 与 Suite 的路由说明没有被改写或弱化。

## 非目标

- 不修改 ProMax runtime、schema、知识库或触发协议。
- 不更换仓库网站、不制作独立落地页。
- 不把 README 写成模型广告，也不将 CrossFrame 理论作者身份转移给模型。
- 不用不可验证的性能比较或未经用户提供的 token 基准。
