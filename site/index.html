CROSSFRAME · V8 STRUCTURAL REASONING RUNTIME

把一次判断，
跑成一条可对账的运行链。

CrossFrame ProMax 是 v8-only、精确点名的独立结构推演 runtime。 它不是"让模型多想一会儿"的提示词，而是把 v8 全源知识、概念闭合、真实检索、反方攻击、明确裁决、完整长文与机器校验，锁进同一次有状态的运行——每一步都留下工件，每个工件都可以被验证，验证失败则定向修复。

按五个方向搜寻案例、支持证据、反例与边界条件，支持与反例分开登记。有网络时外部校准；断网时诚实降档——不伪造来源，也不伪造"检索已完成"。

§01 · RUNTIME, NOT PROMPT

不是更长的提示词，
是一个有状态的运行时

常见的"深度思考"，只是让模型在同一段上下文里多说几句。ProMax 走的是另一条路：有状态、有工件、有验证闸。问题与 v8 源快照先被冻结；概念闭合、局部世界、命题路径与检索结果被登记为可检查的工件；初稿必须先接受最强反方的攻击、完成立场锁定，然后才由 reader projection 把整个审计闭包，投影成一篇普通读者能够进入的中文长文。

一次完整运行交付四份公开产物——dossier、concept atlas、cases 与纯读者 essay——外加内部的 prose review 与 manifest。正文不再转储审计台账；发布状态由独立校验报告决定，而不是由生成它的那个模型自己盖章。

§02 · RUN CHAIN

十三个节点，一条可验证的链

01request冻结请求。推演途中悄悄改题、换证据、移动判断标准——都会被登记发现。
02v8 full-source连续读取 v8 全源快照：3,863 个段落与 117 张表，逐次留下 read event 与 hash。
03concept closure709 个概念逐项处置：定义、邻接、误用边界，以及进入或退出本次推演的理由。
04local world model把对象显式建模为局部世界：行动者、圈层、尺度、双通道、时钟、事件、证据与未知项——分离已知、推断和待证，阻止单一视角冒充全局。
05claim-path中心命题绑定路径 DAG：竞争机制、条件预测、切换条件与撤回条件。结论不以修辞强度代替机制解释。
06retrieval五向真实检索，支持与反例分开登记。断网只能诚实降档，不能伪造来源。
07red-team构造最强反方，检查概念误用、立场稳定性与证据截止——反例拥有真实机会改写、降档或推翻初稿。
08position lock攻击结束后必须锁定立场。"各有道理"不是一个可以交账的出口。
09reader projectionP9 用八个有序动作成文：现实入口、中心命题、机制递进、同维比较、最强反方、明确立场、撤回与行动边界、余味结尾。
10dossier · atlas · cases · essay物化四份公开产物，共同承担完整性——正文不转储台账，台账也不冒充正文。
11prose review六个角色中的最后一个只审校当前正文，生成绑定 essay 与 P8/P9 锁的内部审校结果。
12validatorfresh validator 只接受绑定当前字节的审校结果——审的必须就是发的这一版。
13phase-aware repair失败依据 affected_phase 定向修复：只重置受影响阶段及其下游产物，能补生成的补生成，该降档的降档，该撤回的撤回。

§04 · MODEL FLAVOR SUPPRESSION

六道结构约束，
抑制宿主模型的自身风味

不同 AI 有不同的训练偏好：有的倾向顺从，有的先反驳，有的习惯列举却不裁决。ProMax 不假设能抹去这些差异——它用六道结构约束，限制这些偏好对判断与表达的支配。

v8 定义优先

框架原文与概念契约，覆盖模型预训练中碰巧同名的概念——禁止用"熟悉的词义"替代 CrossFrame 的独特定义。

冻结关键工件

请求、源快照、证据边界、命题与阶段产物被显式登记，防止推演中悄悄改题、换证据、或移动判断标准。

检索与反方攻击草稿

真实案例检索和最强反方不是装饰性章节，而是可以迫使初稿改写、降档或撤回的独立步骤——不能只顺着用户说。

Position lock 强制裁决

攻击之后必须给出明确立场与判断撤回条件。未被要求建议时只完成判断，不自行制造方案——"各有道理"不是逃避判断的出口。

固定成文声口与读者投影

内置 50 张独立技法卡与九种体裁路由，每次只选 3 张核心卡、至多 2 张辅助卡；核心概念绑定 2–4 个逐字来自 v8 的锚词。正文既不自动迎合，也不为了显得独立而自动反对。

独立审校与阶段修复

第六角色逐项审查现实入口、论证依赖、概念保真、证据绑定、反方、公平比较、判断一致性、撤回边界、固定声口——以及宿主模型风味与审计泄漏本身。失败回到 P10 或其真实根因阶段。

这些约束不追求让不同模型的措辞一字不差。它们要求的是：差异必须暴露在证据、路径、反例和撤回条件中，而不能藏进模型的习惯里。

§05 · TRIGGER BOUNDARY

触发边界：仅此四名

ProMax 的触发边界比家族里任何一个 skill 都窄。它只接受以下四种精确名称——不多一个，不少一个。

EXACT NAMES · 4 僅此四名
crossframe-promax CrossFrame ProMax $crossframe-promax /crossframe-promax
  • 点名成立后，宿主读取的唯一规范入口是 skills/crossframe-promax/SKILL.md；各平台镜像只是分发拷贝，不是第二入口。
  • 仅说"最大算力""全尺度""穷尽推演"——不构成 ProMax 点名。泛化的最大化请求，仍然归 Max。
  • Suite 不会把普通 Max 或任何重型任务自动升级为 ProMax。
  • Max 与 ProMax 同时被精确点名——ProMax 优先；一旦进入 ProMax，不得降级回 Max。
  • ProMax 自带生成 → 反证 → 校验 → 修复的独立闭环：不追加 crossframe-review，也不复用 Max 的 repair 或 audit 链。

它是单次观察，不是通用 benchmark、平均值或固定成本。请只在确实需要时显式点名，并预先确认模型额度、上下文续跑能力和成本上限。
